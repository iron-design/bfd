## 1. 문제 정의

### 표면 문제
기존 뽀모도로 앱은 '얼마나 집중했는가'만 설계하고 '회복이 실제로 일어났는가'는 사용자에게 방치한다.

### 본질적 문제 (5 Whys로 도출)
뽀모도로의 원본 설계가 회복을 빈칸으로 남겼고, 측정이 어려워서 앱들도 그걸 그대로 복사했다. 시도한 앱들은 일반론 콘텐츠("스트레칭해라")로 접근해 잔소리 취급받고 후퇴했다. **회복을 콘텐츠가 아닌 측정+피드백 루프로 풀면, 남들이 못 넘은 벽이 곧 해자가 된다.**

### 현재 사람들이 푸는 방식 (As-is)
1. **SNS/폰 전환** — 회복처럼 느껴지지만 2차 컨텍스트 스위칭. 5분이 30분.
2. **아예 안 쉼** — 흐름 끊기 싫어 타이머 무시. 나중에 한 번에 방전.
3. **죄책감 쉼** — 몸만 멈추고 "이래도 되나" 불안으로 정신은 안 놓임.

공통: "쉰다"는 행위는 있는데 "회복됐다"는 결과가 없다. **핵심 빈틈은 인식(awareness) 자체의 부재.**

### Why now?
- **문화**: 번아웃·회복이 일상어가 됨. "회복을 챙긴다"는 메시지가 이제야 팔리는 시대.
- **환경**: 숏폼·알림·상시 연결로 주의력 환경 급격히 악화. 집중 회복의 체감 필요 역대 최고.
- **기술**: 셀프 체크인 UX, 개인 데이터 기반 패턴 추출이 예전보다 훨씬 저렴해짐.
- **도구**: AI로 비개발자도 측정 로직·데이터 파이프라인을 직접 만들 수 있게 된 시점.

## 2. 타겟 & JTBD

### 페르소나
**민준** / 7년차 시니어 프로덕트 디자이너 / B2B SaaS
- 딥워크 업무(복잡한 플로우 설계, 디자인 시스템, 스펙 문서). 한번 물면 깊이 들어가야 하고 전환 비용이 큼.
- 자기 시간에 대한 통제권 있음. 오후 딥워크 블록을 스스로 잡을 수 있는 재량.
- 총량이 아니라 **질과 지속가능성**으로 평가받는 위치. "이 속도로 몇 년 더는 위험하다"는 자각.
- 감성 위로형보다 **자기 최적화 근거(데이터)**에 반응하는 층.

### Job Story

**[토대] 기본기**
> When 매일 딥워크 블록을 시작할 때,
> I want to 알림·인터벌·기록이 군말 없이 안정적으로 돌아가는 뽀모도로를 쓰고 싶다,
> so I can 도구를 의심하지 않고 일에만 몰입할 수 있다.

**[코어 1] 측정 — 인식 부재를 깨는 것**
> When 오후 딥워크 블록에서 다음 뽀모를 시작하려 할 때,
> I want to 직전 휴식이 진짜 회복이었는지, 그냥 폰 본 5분이었는지 알고 싶다,
> so I can 회복 안 된 채 다음 블록에 들어가 밀도를 깎아먹는 걸 막을 수 있다.

**[코어 2] 루프 닫기 — 시니어가 반응하는 지점**
> When 하루·한 주를 돌아볼 때,
> I want to 내 회복의 질이 그날 오후·주 후반의 집중 밀도와 어떻게 연결됐는지 데이터로 보고 싶다,
> so I can 감이 아니라 근거로 내 최적 리듬을 찾고 지속가능하게 일할 수 있다.

### Value Proposition
- **Who**: 딥워크하는 젊은 시니어급 지식노동자 (자기 시간 통제권 있는 사람)
- **Why**: 밀도와 지속가능성으로 평가받는데, 오후·주 후반 밀도 꺾임 = 성과 손실 + 번아웃 리스크
- **What before**: 뽀모 앱이 집중만 세주고 회복 방치. 폰 전환 / 안 쉼 / 죄책감 쉼. 못 쉬는 걸 모름.
- **How**: 회복 셀프 체크인으로 인식을 깨우고, 회복→성과 데이터 루프로 닫음. 콘텐츠가 아닌 측정.
- **What after**: 회복 부실 이월 감소. 감 대신 근거로 최적 리듬 발견. 오후 끝까지 밀도 유지. 지속가능성 통제감.
- **Alternatives**: 집중 앱(Forest 등)은 작업만, 브레이크 앱(Stretchly 등)은 몸만. 정신 회복을 측정하고 성과 루프로 닫는 곳은 없음.

## 3. 임팩트 가설

### North Star Metric
회복 양호 후 다음 뽀모 완주율 vs 회복 부실 후 완주율 격차 (인과 증명).

> 4주 검증용 대리지표: 체크인 결과 '회복 안 됨' 비율이 첫 주 대비 감소 (인식 각성).

### Input Metrics
1. **휴식 체크인 완료율** — 체크인을 실제로 하는 비율. 0이면 아무 데이터도 안 쌓임.
2. **휴식 행동 변화율** — '회복 안 됨' 후 다음 휴식을 다르게 보내는 비율. 인식→행동 다리.
3. **하루 다중 블록 사용률** — 하루 2사이클 이상. 블록 간 비교가 생기는 밀도.

### 정성적 임팩트
> "쉬는 걸 이렇게 신경 쓴 적이 없었는데, 오후 늦게까지 집중이 안 무너지는 게 처음으로 느껴져요."

## 4. 솔루션 (MVP)

### 핵심 가치 한 문장
집중 시간만 세는 뽀모도로에, 회복이 실제로 됐는지 되묻는 층을 얹어 밀도를 오래 유지시키는 앱.

### 솔루션 형태
데스크탑 웹앱 / Next.js / Supabase(DB) / Vercel(배포) / 단일 유저, 로그인 없음.

### Must-have 기능
1. **뽀모도로 기본기** — 집중/휴식 타이머, 인터벌 설정, 안정적 알림 (튼튼하게만)
2. **휴식 종료 시 회복 셀프 체크인** (수 초, 원탭 수준) — 코어 1
3. **즉시 피드백** — 체크인 결과를 사용자에게 되비춰 인식을 깨는 최소 장치
4. **한 사이클 완결** — 뽀모 → 휴식 → 체크인 → 다음 블록 연결

### Should-have
- Supabase 세션 누적 → 블록 간 비교 (회복 양호 vs 부실)
- 하루/주 단위 간단 회고 뷰

### Non-goals (이번엔 안 할 것)
- 로그인/유저 계정, 멀티유저
- 마리모 등 캐릭터 그래픽 (2단 로켓 — 검증 후 Phase 2)
- 행동 기반 자동 회복 감지 (폰·화면 전환) — 열린 가설, 추후 검증
- 태스크 관리, 외부 연동, 모바일, 설치형 래핑

### Demo Flow (4주차 시연)
1. **집중 블록 시작** — 타이머 돌리고 딥워크. 기본기가 군말 없이 도는 걸 짧게 보여줌.
2. **휴식 → 회복 체크인** ← 🔥 데모 하이라이트. "폰 보다 옴 / 회복 안 됨"으로 응답 → 앱이 "방금 그건 회복이 아니었다"를 되비추는 순간.
3. **블록 간 비교** — 회복 양호 vs 부실 다음의 집중 결과를 나란히. 북극성을 눈으로 보여줌.
4. **하루/주 회고** — 회복 잘 된 날의 오후가 밀도 유지됐다는 리듬 뷰. 정성 임팩트 착지.

## 5. 리스크 & 가정

### VUVF 가정 매핑

| 카테고리 | 가정 | 위험도 |
|----------|------|--------|
| **Value** | 사람들이 못 쉬는 걸 "몰라서"인가, "알면서 안 하는" 건가? 후자면 체크인은 잔소리. | 🔴 최고 |
| **Value** | 회복↑→집중↑ 격차가 데이터에 실제로 나타나나? 다른 변수에 묻힐 수 있음. | 🟡 중 |
| **Usability** | 휴식 끝 체크인이 마찰로 느껴져 스킵당하지 않나? Input ① 무너지면 코어 죽음. | 🟡 중 |
| **Viability** | 주당 6시간으로 로컬 루프 + Supabase + 배포가 4주에 되나? | 🟡 중 |
| **Feasibility** | 브라우저 백그라운드 타이머 스로틀링. 기본기 신뢰 깨짐. | 🟢 낮음 |

### 가장 위험한 가정 (Top 1)
**V-①**: "되물으면 행동이 바뀐다" — 코어 전체가 이 위에 얹혀 있음. 알면서 안 하는 거라면 방향 전환 필요.

### 1주차 검증 실험 (코드 없이)
본인 도그푸딩 + 주변 3~5명에게 체크인 며칠 시켜보고 **"되물으니 휴식 방식을 실제로 바꾸더냐"(Input ②)**를 관찰. 안 바꾸면 = "인식 각성"에서 "행동을 더 쉽게/매력적으로"로 방향 전환.

## 6. 주차별 마일스톤

### 1주차: 로컬 루프 프로토타입 + V 검증 착수
- **목표**: Must 달성 = 안전선 확보
- **산출물**:
  - [ ] 로컬 프로토타입 (뽀모→휴식→체크인→다음 블록 한 사이클 완결)
  - [ ] 타이머 정확도 확인 메모 (F 리스크 방어)
  - [ ] 도그푸딩 며칠치 기록 (U + V 초기 관찰)
  - [ ] GitHub PR

### 2주차: Supabase 연동 + 블록 간 비교
- **목표**: 코어 2 데이터 소스 작동
- **산출물**:
  - [ ] 세션 누적·저장 프로토타입 (새로고침해도 유지)
  - [ ] 블록 간 비교 뷰 초안
  - [ ] DB 스키마 문서
  - [ ] GitHub PR

### 3주차: Vercel 배포 + 피드백 수집
- **목표**: V 신호 수집 (앱 완성도보다 중요)
- **산출물**:
  - [ ] 공개 배포 URL (Vercel)
  - [ ] 3~5명 피드백 + "되물으니 바꾸더냐" 관찰 기록
  - [ ] 시드 데이터 or 실사용 데이터 (빈 대시보드 방지)
  - [ ] GitHub PR

### 4주차: 다듬기 + 발표
- **목표**: 데모 + 검증 결과 정리
- **산출물**:
  - [ ] 최종 배포 URL
  - [ ] 데모 영상 or 라이브 데모 (5D 4단계, 2번에 시간 몰빵)
  - [ ] 검증 결과 문서 (V 가정 결과 + 배운 것 + 다음 스텝)
  - [ ] 회고 & 로드맵 한 장 (마리모 2단 로켓, 인과 검증 등)

### 설계 원칙 (빌드 내내 참고)
1. **토대는 튼튼하게, 회복은 뾰족하게** — 차별화 에너지는 코어에 몰빵
2. **로컬 루프 먼저, 인프라는 나중** — 좋은 도구일수록 인프라부터 짓는 함정 조심
3. **상태값 먼저, 캐릭터는 나중** — 회복 상태를 추상값으로 두고 마리모는 표현 레이어로 분리
